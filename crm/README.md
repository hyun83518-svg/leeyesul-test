# 아르테파인 CRM 데이터 작업 공간

## 구조

```
crm/
├── data/raw/            # 원본 내보내기 파일 (개인정보 포함, git 미추적)
├── scripts/build_crm.py # 정규화 → 회원관리·RCA·결제·예약이력·발송명단 병합 → 생애단계·VIP → 세그먼트·페르소나 → 발송 전환 대조 → 출력
├── output/
│   ├── CRM_마스터_<기준일>.xlsx   # 회원 마스터 + 세그먼트·페르소나·RCA·발송 시트 (개인정보 포함, git 미추적)
│   ├── CRM_타겟통합_<기준일>.xlsx # 타겟별 통합본: 0_요약 카탈로그 + 우선순위 A/B/C/X 타겟 시트 + 제외명단·캠페인성과·발송이력·라인업
│   ├── summary.json              # 집계 요약 (개인정보 없음)
│   └── 분석요약.md               # 집계 요약 마크다운 (개인정보 없음)
├── docs/                # 전략 문서(docx → md 변환본)
├── CRM_액션플랜.md      # 분석 결과 기반 마케팅 실행 계획
├── 전략문서_데이터매핑.md # 전략 문서 페르소나 ↔ 보유 데이터 매핑, 부족 데이터 목록
└── README.md
```

## 실행

```bash
pip install pandas openpyxl
python3 crm/scripts/build_crm.py            # raw/ 의 최신 '*전체*.xlsx' 사용
python3 crm/scripts/build_crm.py --master crm/data/raw/회원설문_2026-09-01_전체.xlsx
```

## 새 데이터가 들어올 때 — 파일만 넣고 실행하면 된다

정기 갱신에 필요한 파일은 세 가지다. 아래 이름 규칙으로 `crm/data/raw/`에 넣고 `python3 crm/scripts/build_crm.py`를 실행하면 마스터·타겟통합·요약이 모두 다시 만들어진다.

| 무엇 | 파일명 규칙 | 주기 | 없으면 생기는 일 |
|---|---|---|---|
| 회원 설문 내보내기(전체) | `회원설문_<YYYY-MM-DD>_전체.xlsx` | 회차 전(1~2주) | 신규 회원·동의 변경이 반영 안 됨. 가장 최신 날짜가 마스터가 되고 옛 파일은 추이용으로 남긴다 |
| 결제상세(전 지점) | `결제내역_<YYYY-MM-DD>_전체.xlsx` (시트 `결제상세`) | 회차 D+14마다 | 생애단계·최근성·전환 대조가 멈춤. 기간이 겹쳐도 (결제일, 고객명, 예약일, 차종)로 중복 제거되니 넉넉히 뽑아도 된다 |
| 발송 명단 | `발송명단_<발송일 YYYY-MM-DD>_<발송시각 HHMM>_<캠페인코드>.xlsx` (예: `발송명단_2026-09-18_1830_ys-night.xlsx`, 시각은 생략 가능) | 회차마다 | 그 회차의 전환·수신자 프로필이 빠짐. `연락처` 또는 `전화번호` 컬럼이 있는 시트는 전부 수신자로 읽고, 시트명에 `홀드아웃`이 있으면 대조군으로 읽는다. 시트명에 제외·보류·참고·요약·문안·설명·라인업·차종·검증이 있으면 건너뛴다 |

선택 파일(있으면 좋고 없어도 돌아간다):

| 무엇 | 파일명 규칙 | 용도 |
|---|---|---|
| 방문통계 월별 리포트 | `웹분석_<시작일>_<종료일>.xlsx` | 채널·캠페인별 유입·확정 요약(11절). 타겟 추출에는 쓰이지 않는다 |
| 회원 관리 내보내기 | `회원관리_<날짜>_p<페이지>.xlsx` | 실명·닉네임 보강 |
| 레인조 회원 DB | `레인조_*.xlsx` | RCA 교차 갱신 |
| 지점별 결제 파일 | `결제내역_<날짜>_<지점>.xlsx` | 전체 파일 대신 써도 된다(이메일·연락처 컬럼 필요) |
| 현재 차종 현황 | `LINEUP_SOURCES`에 (파일, 시트, 헤더행, 기준일) 추가 | 라인업 시트 |

발송 시각은 파일명의 HHMM → `SEND_TIMES`(회차별 기록) → 10:00 가정 순으로 정해지고 `발송시각_근거` 컬럼에 파일명/기록/추정으로 표시된다. 반응 타이밍 분석(15절)은 이 시각을 기준으로 발송→첫 결제 경과시간을 계산하므로 실제 발송 시각을 파일명에 넣는 것이 좋다.

새 차종이 결제에 나타나면 `MODEL_INFO`에 장르·배기량대를 한 줄 추가한다(없으면 '기타'로 집계된다). 운영 정책 상수는 `SEND_TO_UNASKED`(설문 도입 전 미응답자 발송 여부)와 `RCA_HEAVY_MIN`(R1 헤비 기준). 타겟 정의는 `TARGET_DEFS`, 세그먼트는 `SEGMENT_DEFS`, 페르소나는 `PERSONA_DEFS`.
